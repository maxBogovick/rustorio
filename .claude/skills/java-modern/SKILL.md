# Java 25 и идиома rustorio

Здесь только то, что **проверяется и датируется**: версии фич и адреса живых примеров.
Общего пересказа SOLID, GoF и Effective Java здесь нет намеренно — см. последний раздел.

## Статус фич JDK 25 — сверено 01.08.2026

Правило проекта: **любая preview-фича запрещена**, `--enable-preview` в сборке не включён.

| Фича | JEP | Статус в 25 | Можно? |
|---|---|---|---|
| Flexible Constructor Bodies (валидация до `super()`) | 513 | финал (был preview с 22) | **да** |
| Scoped Values | 506 | финал | да, но многопоточности в тике всё равно нет |
| Module Import Declarations | 511 | финал | да, применимость сомнительна |
| Compact Source Files, Instance Main Methods | 512 | финал | для точек входа не нужно |
| Compact Object Headers | 519 | финал, рантайм | флаг JVM, не код |
| Generational Shenandoah | 521 | финал, рантайм | флаг JVM, не код |
| **Stable Values** | **502** | **preview** | **нет** |
| **Structured Concurrency** | **505** | **preview** (пятый заход) | **нет** |
| **Примитивы в паттернах, `instanceof`, `switch`** | **507** | **preview** (третий заход) | **нет** |
| Vector API | 508 | incubator (десятый) | нет |

Доступно и без оговорок, как в любой современной Java: `record`, `sealed` там, где множество
действительно закрыто, pattern matching в `switch` и `instanceof`, деконструкция записей,
`switch`-выражения, sequenced collections, текстовые блоки.

**Как перепроверить, а не верить этой таблице.** Список JEP выпуска —
[openjdk.org/projects/jdk/25](https://openjdk.org/projects/jdk/25/); статус конкретной фичи —
`https://openjdk.org/jeps/<номер>`. Вышел новый JDK — таблица выше устарела целиком, и это
нормально: обновляется одним заходом по ссылке, а не догадками.

## Что проект использует сегодня

`record` — основная форма значения, `Optional` — только возврат, pattern matching в `instanceof`
применяется, `EnumMap`/`EnumSet` живут там, где ключ действительно enum, текстовых блоков нет.
Настоящий `sealed` в проекте один — `persistence/SaveResult.java`; остальные совпадения по слову
`sealed` это javadoc, и сам этот факт — иллюстрация последнего раздела.

`sealed` осознанно снят с `Building`: движок должен принимать классы модов, которых нет в
`permits`. Не возвращай его туда «ради исчерпывающего `switch`» — это прямой откат главной цели.

Считать, а не помнить: `grep -rl 'public record ' src/main/java | wc -l` и аналогично. Числа тут
не записаны намеренно — записанное число устаревает молча, команда не устаревает никогда.

## Настоящий свод правил — машинные проверки

Документ говорит «соблюдай Open/Closed». Эти проверки считают, соблюдён ли он, и не дают
ухудшить результат:

| Проверка | Что ловит |
|---|---|
| `ContentCouplingRatchetTest` | новый `switch`/`instanceof` по типу контента — храповик не даёт увеличить число |
| `PackageBoundaryRulesTest` | пять границ слоёв по байт-коду: домен не знает про рендер и libGDX, Jackson только в persistence/mod |
| `PackageInfoRulesTest` | `package-info.java` с `@NullMarked` в каждом пакете |
| `SourceTextRulesTest` | wildcard-импорты, расползание `var`, новые цитаты ID задач в комментариях |
| NullAway на `compileJava` | null-контракт не «на словах» |
| `GoldenSaveTest` | смена формата сейва без бампа версии |
| `./gradlew benchmark` | мс/тик выше порога — команда возвращает ненулевой код |

Проектная записка (`/design-note`) должна отвечать на вопрос «сдвинет ли моя правка храповик»,
а не «применил ли я паттерн».

## Доказательство существования символа

`grep` доказывает, что **текст встречается**, и ничего больше. Упоминание в javadoc, в имени
другого класса, в комментарии — всё это совпадения. 01.08.2026 на этом сгорели четыре вердикта
подряд: `SpeedModule`, `Building.unwrap`, `BuildingFactory.attachBelt`, `BuildingMemento`
«находились», хотя их в коде нет.

Поэтому: **утверждение «метод/класс существует» доказывается компилятором или языковым сервером,
а не поиском по тексту.**

- Языковой сервер (плагин `jdtls-lsp`) — go-to-definition, find references, тип по наведению.
  Требует бинаря: `brew install jdtls`.
- Без него — компиляция: код, который зовёт несуществующий метод, не соберётся.
- Крайний случай — `grep` по **объявлению** (`class X`, `X(` в сигнатуре) плюс проверка, что файл
  существует. Это слабее, и в отчёте так и надо называть.

## Чего здесь нет и не будет

Пересказа SOLID, каталога GoF, «принципов чистого кода». Причина не в лени: 01.08.2026 аудит
показал, что **все найденные ошибки жили в прозе, пересказывающей факты**, а машинные проверки не
соврали ни разу. Каждый абзац такого пересказа — будущая ложь, которую никто не заметит.

Общая инженерная культура у модели уже есть. Ценность даёт то, чего она знать не может:
версии фич, адреса образцов и проверки, которые ловят ошибку без человека.
