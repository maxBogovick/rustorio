# Claude Code — специфика этого репозитория

`AGENTS.md` выше — основной свод правил (он же читается Codex/Cursor/Copilot).
Здесь только то, что относится к Claude Code и не дублирует его.

## Зачем этот проект

`GDD.md` — единственный документ про «зачем», а не «как»: питч, три столпа дизайна,
раздел «Вне рамок». Сверяйся с ним, когда решение затрагивает игру, а не только код.
Проектная записка до кода (требование `AGENTS.md`) должна показывать, какому столпу
служит решение. Продуктовые решения принимает владелец — предлагай, не внедряй.

## Порядок работы

1. Новая задача — новая сессия (`/clear`). Не смешивай несвязанные задачи в одном контексте.
   Полный цикл по карточке движка — `/engine-card` (вызывает владелец).
2. Сначала ориентировка ([`docs/start-here.md`](docs/start-here.md) — куда смотреть) и
   проектная записка (`/design-note`), потом код.
3. После каждой правки Java-файла компиляция запускается автоматически (hook) — не нужно
   звать `./gradlew compileJava` руками.
4. Завершить ход с красной сборкой нельзя: `Stop`-hook гоняет `./gradlew build`, когда в
   рабочем дереве есть изменённые `.java`.
5. Перед тем как считать задачу сделанной — ревью дифа в свежем контексте
   (`/code-review` или субагент `rustorio-reviewer`). Тот, кто писал, не ставит себе оценку.

## Чем доказывается утверждение

Любое утверждение о состоянии репозитория сопровождается выводом команды. Нет вывода — это
догадка, и называть её надо догадкой.

**Существование символа `grep`-ом не доказывается.** Поиск по тексту находит упоминания в
javadoc, комментариях и чужих именах. Метод и класс проверяются компилятором или языковым
сервером (`jdtls-lsp`); `grep` по объявлению — слабое доказательство, и в отчёте называй его
слабым. Справка и разбор случая — `/java-modern`.

## Что где лежит

- `AGENTS.md` — правила кода, архитектурные границы, ловушки репозитория.
- `GDD.md` — видение игры. В контекст сам не загружается — открой его перед проектной запиской.
- `.claude/rules/` — правила по областям; подгружаются сами при чтении файла из своей области.
- `doc_temp/` — одноразовые рабочие записи владельца, **вне git и часто устаревшие**. Открывай
  файл оттуда, только если владелец назвал его в этой сессии, и **никогда не читай целиком**:
  отдельные файлы там в сотни килобайт, один такой съедает почти всё окно. Делегируешь чтение
  субагенту (`Explore`, `Plan`) — повтори запрет в задании: эти двое `CLAUDE.md` не получают.

## Ограничения окружения

- Окно игры (`./gradlew run`, `devRun`) в headless-сессии не запускается. Что не
  проверено — пиши прямо, «проверено визуально» доказательством не считается.
- Бенчмарк меряй локально: в CI его нет и не будет — на общих раннерах разброс времени слишком
  велик, чтобы порог что-то значил. Вердикт выносит сама команда, читать глазами нечего.
