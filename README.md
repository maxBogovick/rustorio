# Rustorio 🏭 — учебный каркас

Это **точка старта курса**: мини-Factorio на Java 25 + [libGDX](https://libgdx.com/),
из которой вы шаг за шагом соберёте настоящую игру — с бурами, лентами, печами,
исследованиями, отменой действий и сохранениями.

Каркас уже умеет главное и трудное:

- **окно и игровой цикл** `input → update → render` с фиксированным тиком;
- **мир из чанков 32×32**, которые создаются лениво — только когда в них заглянули;
- **руду как функцию от координат** — детерминированная генерация карты;
- **камеру**: скролл (WASD/стрелки/средняя кнопка), зум колесом к точке под курсором,
  перевод «пиксель мыши → клетка мира»;
- **отрисовку карты** с отсечением невидимого (culling) и подсветкой клетки под курсором;
- **атлас спрайтов** (все картинки склеены в одну текстуру при старте) — спрайты уже
  ждут ваших зданий;
- **тесты** — обычные (`WorldTest`, `GameCameraTest`) и архитектурные
  (`ArchitectureTest` на ArchUnit): они стерегут слои и детерминизм на каждой сборке.

Больше в игре нет **ничего**. Ни одного здания, ни одного предмета, ни одной строчки
симуляции. Всё это — ваша работа в курсе.

## Запуск

Нужен только сам проект: Gradle сам скачает JDK 25 и все зависимости.

```bash
./gradlew run     # окно откроется сразу: тёмное поле, синие пятна — руда
./gradlew test    # все тесты обязаны быть зелёными В ЛЮБОЙ момент курса
```

## Управление (пока)

| Действие | Клавиши |
|----------|---------|
| Двигать камеру | **WASD** / стрелки / зажать **среднюю кнопку** мыши |
| Зум | **колесо мыши** (к точке под курсором) |
| Пауза | **Пробел** |

Клетка под курсором подсвечивается рамкой, её координаты видны в HUD сверху.

## Карта проекта

Слои. Стрелки зависимостей смотрят **вниз**: верхний слой знает про нижний, не наоборот.
Ядро (`core` + `model` + `game`) не зависит от libGDX и тестируется без окна — это
проверяется автоматически (`ArchitectureTest`).

| Пакет | За что отвечает | Появится по ходу курса |
|-------|-----------------|------------------------|
| `core` | словарь и настройки: `Config` | `Direction`, `Item`, `Tool`, баланс |
| `model` | мир: `World` (фасад), `Chunk`, `Tile`, `OreMap`, `Cell` | здания, рецепты, транспортные линии |
| `game` | состояние между кадрами: `GameState`, фиксированный тик | инструменты, история отмен |
| `render` | отрисовка: `Renderer`, `GameCamera`, `Textures`, HUD | слои зданий и предметов |
| `input` | ввод: `InputHandler` (камера, пауза) | строительство, горячие клавиши |
| `screen` | `GameScreen` — крутит игровой цикл | почти не меняется |

### Золотое правило: однонаправленный поток данных

```
   [ игрок ]                         [ экран ]
       │                                 ▲
       ▼                                 │
    input  ───►  GameState/World  ───►  render
   (МЕНЯЕТ)         (МЕНЯЕТ              (только
                   по тикам)             ЧИТАЕТ)
```

- **input** меняет мир по воле игрока;
- **update** меняет мир по правилам игры, только внутри тика;
- **render** — никогда не меняет мир. Только читает и рисует.

Держитесь этого — и багов «почему у меня что-то поменялось при отрисовке?»
просто не будет.

## Ритм работы

**Правка → `./gradlew test` → `./gradlew run`.**
Тесты ловят «сломал логику», запуск показывает результат глазами.
После каждого шага любой лекции проект обязан компилироваться, а тесты — быть зелёными.
