# 🏭 Rustorio

Мини-Factorio на **Java 25** и **libGDX**: строишь фабрику из буров, лент, печей и
сборщиков на бесконечной сетке, автоматизируешь каждый шаг и бесконечно улучшаешь схему.
Уютная песочница без врагов и боя.

Сейчас проект превращается в **моддируемый движок**: здания, предметы и рецепты
описываются JSON-ом и грузятся как контент мода, а базовая игра — такой же мод
(`resources/mods/rustorio`), как любой сторонний.

> 🎮 Про что игра, три столпа дизайна и что сознательно **не** делаем — в **[GDD.md](GDD.md)**.
> 🤖 Правила работы с кодом (для людей и для агентов) — в **[AGENTS.md](AGENTS.md)**.

## Запуск

Нужен только Git — JDK 25 Gradle скачает сам (toolchain + foojay-resolver).

```bash
./gradlew run
```

| Команда | Что делает |
|---|---|
| `./gradlew run` | окно игры |
| `./gradlew devRun` | окно с готовым dev-стендом: по одному экземпляру каждого здания |
| `./gradlew editor` | веб-редактор контента модов — http://localhost:8787 |
| `./gradlew game` | безголовая логика в консоли, без графики |
| `./gradlew build` | компиляция + NullAway + все тесты + jacoco — главный гейт |
| `./gradlew test` | только тесты |
| `./gradlew benchmark` | замер мс/тик на большой сцене из лент и сундуков |

## Как играть

**Строить и сносить**

- **0…9** — выбрать здание из панели; **B** — полное меню построек (в нём буквы фильтруют список).
- **ЛКМ** — поставить (можно вести линию, удерживая кнопку), **ПКМ** — снести, **R** — повернуть.
- **Ctrl+Z / Ctrl+Y** — отменить/повторить.

**Настроить то, что уже стоит** (наведи курсор на здание)

- **C** — листнуть рецепт печи, пресса или сборщика: чем именно оно занято.
- **F** — листнуть предмет фильтра.
- **G** — забрать содержимое ящика к себе в инвентарь.
- **U** — ускорить здание вдвое (там, где ускорение вообще применимо).

**Смотреть**

- **WASD** или **стрелки** — камера, средняя кнопка мыши — тащить карту, колесо — зум
  (в открытом меню построек колесо листает список).
- **Tab** — книга рецептов, **T** — дерево исследований, **V** — статистика (**N** листает в ней
  предмет), **I** — инфо-экран, **Alt** — оверлей поверх карты.
- **Esc** — закрыть любую открытую панель.
- **Пробел** — пауза, **[** и **]** — скорость симуляции.
- **H** — подсказка по управлению в самой игре, **P** — счётчик FPS/UPS.
- **F5 / F9** — сохранить/загрузить (`rustorio-save.json` в корне, в git не попадает).

Список сверен с кодом ввода (`com.graphics.input`); меняешь клавишу — поправь и здесь.

Базовая цепочка: `Бур (на руде) → Лента → Печь → Лента → Ящик`.

## Устройство

Зависимости смотрят внутрь: графика знает про домен, домен про графику — нет.

| Пакет | За что отвечает |
|---|---|
| `com.rustorio.domain` | внутреннее кольцо: значения и стратегии, не зависит ни от чего |
| `com.rustorio.domain.building` | здания; с миром говорят только через `TickContext` |
| `com.rustorio.domain.world` | сетка, тик мира, размещение и снос |
| `com.rustorio.domain.action` | действия игрока и история отмены/повтора |
| `com.rustorio.api` | публичный API для модов: контент, реестры, события |
| `com.rustorio.mod` | загрузчик модов: JSON-контент, зависимости, изоляция классов |
| `com.rustorio.game` | точка сборки: собирает играбельную игру из загрузчика, домена и сейва |
| `com.rustorio.persistence` | сохранение/загрузка игры в JSON |
| `com.graphics` | рендер, ввод, экраны (libGDX) |
| `src/tools` | dev-инструменты (`Main`, `Benchmark`), не часть игры |
| `src/editor` | веб-редактор контента модов (`./gradlew editor`) — HTTP-сервер + статика в `resources/editor` |

Jackson живёт ровно в двух пакетах — `persistence` (сейв) и `mod` (контент модов); в домене
его нет. Это и остальные границы проверяются не на словах: `PackageBoundaryRulesTest` (ArchUnit)
разбирает байт-код и валит сборку при нарушении. Null-контракт (`@NullMarked`/JSpecify)
проверяется NullAway на каждой компиляции.

## Что можно замоддить

Базовая игра сама загружена как мод (`resources/mods/rustorio`) — всё, что ниже, движок делает
для неё и для стороннего мода одинаково; расхождение ловит `VanillaAsModParityTest`. Мод — это
папка с `mod.json`; данные лежат в `content/`, свои спрайты — в `textures/*.png` рядом. Мод бывает
**на одних данных** (только JSON, без кода) или **с кодом** (плюс `.jar` с точкой входа).

**Свой контент — файлом JSON.** Каждый тип описан схемой в [docs/schemas/](docs/schemas/), а схемы
сверяются с реальным контентом тестом `ContentSchemaTest` — справочник не может тихо устареть.

| Папка | Что добавляешь |
|---|---|
| `content/items/` | предметы (руда, пластина, что угодно) |
| `content/recipes/` | рецепты: из чего, во что, за сколько тиков |
| `content/buildings/` | здания: размер, стоимость, что крафтит |
| `content/kinds/` | пулы рецептов — какой набор умеет здание |
| `content/techs/` | узлы дерева исследований (цена, предпосылки) |
| `content/maps/` | авторские карты — руда и рельеф патчами, не генератором |

**Править чужое, не только добавлять своё.** Всё это — реестры с операциями
`register` / `update` / `remove`, поэтому баланс-мод возможен без форка чужих определений: «сделать
ванильную плавку вдвое медленнее» — это `update` рецепта по его id, а не копия файла, который
принадлежит другому. Технологии теперь тоже реестр (раньше были `enum` — единственная часть игры,
которую нельзя было расширить), а рецепт получил собственный `ContentId`.

**Код-мод — точка входа `RustorioMod`** с четырьмя необязательными шагами. Все моды проходят их
раундами синхронно (сначала `registerContent` у всех, потом `modifyContent` у всех, потом
`finalFixes`), поэтому мод может видеть и править контент другого мода без графа зависимостей на
уровне контента:

1. `registerContent` — регистрируешь свой контент;
2. `modifyContent` — правишь любой уже зарегистрированный, свой или чужой;
3. `finalFixes` — последние поправки перед заморозкой реестров;
4. `subscribeEvents` — подписка на игровые события.

**События, на которые вешается мод** (шина по типу события — добавить новое событие не значит
править список «известных»):

| Событие | Когда |
|---|---|
| `WorldInitEvent` | мир создан, ещё ничего не произошло |
| `BuildingPlaceEvent` | игрок ставит здание — **можно отменить** (`cancel()`) |
| `BuildingPlacedEvent` | здание уже поставлено |
| `TickEvent` | тик мира завершился |
| `ItemProducedEvent` | здание выпустило предмет |
| `ResearchCompleteEvent` | технология открыта |

`BuildingPlaceEvent` спрашивается только при действии игрока — никогда при загрузке сейва или
отмене, чтобы мод не мог удалять здания из готовой фабрики просто фактом установки.

**`mod.json` умеет:**

- `dependencies` — от каких модов зависит; загрузчик сам строит порядок и ловит цикл;
- `minEngineVersion` — минимальная версия движка; мод для более нового движка отклоняется понятным
  сообщением, а не падает позже внутри своего кода;
- `renames` (`старый-id → новый-id`) — переименованное здание в старом сейве восстанавливается, а не
  считается пропавшим контентом;
- `name` / `description` / `authors` / `homepage` / `license` — чем мод подписан в списке.

**Что движок гарантирует моддеру:**

- **порядок контента детерминирован** — id нумеруются по алфавиту `ContentId`, а не по порядку
  загрузки, поэтому дамп, UI, сейв и хеш одинаковы от запуска к запуску независимо от набора модов;
- **сломанный мод не роняет игру** — он пропускается, причина уходит в лог загрузки, список
  пропущенных виден в главном меню; зависимые от него выпадают следом;
- **сейв переживает смену модов** — переименованное восстанавливается по `renames`, технология
  удалённого мода при загрузке тихо отбрасывается, отсутствующий контент не роняет загрузку.

## Как начать свой мод

| Что нужно | Куда идти |
|---|---|
| Сделать первый мод с нуля | **[docs/first-mod.md](docs/first-mod.md)** — своя руда за 20 минут, без Java |
| Написать мод с кодом (jar) | [docs/howto/code-mod.md](docs/howto/code-mod.md) — своё поведение и подписка на события |
| Решить конкретную задачу | [docs/howto/](docs/howto/) — здание, текстуры, правка чужого рецепта |
| Посмотреть, какие бывают поля | [docs/reference.md](docs/reference.md) и схемы в [docs/schemas/](docs/schemas/) |
| Понять, почему движок устроен так | [docs/why-registries.md](docs/why-registries.md) |

Схемы подключаются в редакторе (VS Code, IDEA) — тогда опечатка в поле подчёркивается сразу, а не
находится запуском игры; как именно, написано в справочнике. Образцы: базовый мод
`resources/mods/rustorio` (он же и есть ванильная игра, выраженная данными) и `examples/examplemod`
— мод с данными **и** кодом на Java, который собирается и проверяется в каждой сборке.

Контент удобнее не писать руками, а через веб-редактор (`./gradlew editor`,
http://localhost:8787): создаёт и правит все перечисленные типы контента с проверкой на лету,
включая редактор карт (руда/рельеф патчами прямо на холсте, полноэкранный) и загрузку своих
текстур — и запускает игру на открытой карте одной кнопкой (Play).
