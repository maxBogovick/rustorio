# Как добавить жидкость и жидкостную машину без Java

Жидкость и машины вокруг неё описываются данными ровно так же, как предметы и здания. Новая
**жидкость** — это новый файл, а не флаг на предмете: труба возит `FluidType`, лента — `ItemType`,
и перепутать их нельзя. Новая **жидкостная машина** — это здание на одном из готовых архетипов
(`PIPE`, `TANK`, `PUMP`, `BOILER`, `GENERATOR`), которому дописали жидкостные порты.

Новое **поведение** (например, машина, смешивающая две жидкости) данными не выражается — для него
нужен jar-мод, как и для любого другого нового поведения.

## Своя жидкость

`content/fluids/acid.json`:

```json
{
  "path": "acid",
  "label": { "en": "Acid", "ru": "Кислота" },
  "colorRgb": "#8FdE3A"
}
```

Три поля, все обязательные: `path` (id в пространстве имён твоего мода), `label` (строка или
`{en, ru}`) и `colorRgb` (`#RRGGBB`). Цвет — не украшение: им красится полоска заполнения в трубе
и подсветка сети в оверлее (Alt), так что две жидкости стоит делать разного цвета.

Температуры, давления и скорости потока у жидкости нет намеренно — жидкость это имя, объём и цвет,
пока что-то в игре не читает большего.

## Труба и бак

Труба и бак — один архетип `PIPE`; бак это та же труба с большим `bufferMax`:

```json
{
  "path": "big_tank",
  "label": { "en": "Big tank", "ru": "Большой бак" },
  "archetype": "TANK",
  "cost": { "item": "rustorio:iron_plate", "amount": 20 },
  "placement": "NEEDS_PASSABLE_TERRAIN",
  "texture": "mymod:big_tank",
  "bufferMax": 5000,
  "acceptsSpeedEffects": false
}
```

`bufferMax` — сколько держит **одна клетка**. Вся связная сеть труб это одно ведро: её ёмкость —
сумма `bufferMax` всех клеток, а «насколько полна труба» одинаково у каждой клетки сети. Труба
ничего не «тикает» — за тик сеть не трогает никто, кроме машин на её краях.

## Насос: производит жидкость у воды

Архетип `PUMP` наливает свой `fluidOutput` в сеть перед собой. Правило размещения
`ADJACENT_TO_WATER` требует клетку воды рядом — это единственное правило, которое жидкостной
машине даёт код движка, данными его не выразить:

```json
{
  "path": "acid_pump",
  "label": { "en": "Acid pump", "ru": "Насос кислоты" },
  "archetype": "PUMP",
  "cost": { "item": "rustorio:iron_plate", "amount": 5 },
  "placement": "ADJACENT_TO_WATER",
  "texture": "mymod:acid_pump",
  "fluidOutput": "acid",
  "acceptsSpeedEffects": false
}
```

## Котёл: жидкость + топливо → другая жидкость

Архетип `BOILER` забирает `fluidInput` из сети позади и топливо-предмет (`fuel`), а `fluidOutput`
отдаёт в сеть перед собой — две разные сети, вода и пар не смешиваются:

```json
{
  "path": "acid_boiler",
  "label": { "en": "Acid boiler", "ru": "Котёл кислоты" },
  "archetype": "BOILER",
  "cost": { "item": "rustorio:iron_plate", "amount": 8 },
  "placement": "NEEDS_PASSABLE_TERRAIN",
  "texture": "mymod:acid_boiler",
  "fuel": "rustorio:coal",
  "fluidInput": "rustorio:water",
  "fluidOutput": "acid",
  "acceptsSpeedEffects": false
}
```

## Электричество: столб, генератор, потребитель

Ток опционален: питания требует только здание, которое объявило `power.demand`. Всё остальное
работает даром, как и раньше. Соединяют сеть **столбы** с радиусом, а не смежность клеток.

```json
"power": { "radius": 5 }        // POLE: покрывает и связывает клетки в радиусе 5
"power": { "output": 60 }       // GENERATOR: даёт 60 мощности за тик (архетип GENERATOR забирает пар)
"power": { "demand": 30 }       // любой архетип: без 30 мощности за тик встаёт и показывает NO_POWER
```

Здание без ключа `power` к электричеству не относится вовсе — это и делает ток opt-in, без
миграции существующих карт.

## Цепочка целиком

```
река ──насос──► [вода] ──► котёл(+уголь) ──► [пар] ──► генератор ──► [ток] ──► электро-машины
```

## Проверка

```bash
./gradlew game
```

Число жидкостей и зданий в сводке загрузки должно вырасти. Ошибку в поле, которое загрузчик читает
(неизвестная жидкость в `fluidInput`, `power` не объект, отрицательное значение внутри него), он
назовёт вместе с модом, файлом и полем.

> **Опечатка в ИМЕНИ поля не будет замечена.** Загрузчик читает известные ему ключи и молча
> пропускает остальные, поэтому `"fluidOutut"` даёт не ошибку, а насос, который ничего не качает.
> Схемы в `docs/schemas/` ловят такое только на верхнем уровне файла и не заглядывают внутрь
> вложенных объектов вроде `power`. Если машина загрузилась, но ничего не делает, — сверь имена
> полей со списком.

Полный список полей —
[schemas/fluid.schema.json](../schemas/fluid.schema.json) и
[schemas/building.schema.json](../schemas/building.schema.json).
