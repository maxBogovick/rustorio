# Урок 1 — Первый тик: бур добывает руду

Мы строим игру-фабрику с нуля. Не «разбираем готовый код», а пишем его сами, по одному
маленькому куску за урок, и после каждого урока игру можно ЗАПУСТИТЬ и увидеть, что она делает.
Начинаем с самого простого работающего кусочка: бур, который раз в несколько тиков выдаёт руду.
Три коротких файла — и первый запуск.

**Правило курса:** сначала — простое и работающее, потом — обобщения. Никаких интерфейсов,
базовых классов и пакетов «на будущее»: они появятся, когда в них возникнет НУЖДА, и тогда будут
понятны. Сегодня всё живёт плоско в пакете `com.rustorio` и предельно прямо.

---

## 1. Тик — сердцебиение игры

Фабрика — это мир, который живёт шагами. Один шаг называется **тик**: все здания чуть-чуть
продвигают свою работу, потом следующий тик, и так далее. Пока у нас одно здание, «мир» — это
просто цикл, который дёргает бур раз за разом.

Начнём без графики. Игра будет **безголовой**: без окна и спрайтов, она просто печатает в консоль,
что происходит. Так логику видно сразу, а окно и картинки добавим отдельным блоком позже, когда
логике будет что показывать.

---

## 2. Предмет

Первое, что есть в игре, — предмет. Пока он один:

```java
// com/rustorio/Item.java
public enum Item {
    IRON_ORE
}
```

Одно значение — намеренно. Перечисление вырастет, когда появится, ЧТО в него добавить (плита,
шестерёнка). Пустые варианты «про запас» не заводим: каждый появится под конкретную нужду.

---

## 3. Бур

Бур — первое здание. И это пока **обычный класс**, без интерфейсов и базовых типов:

```java
// com/rustorio/Miner.java
public final class Miner {

    private static final int MINE_TIME = 3;   // за сколько тиков готовится порция руды
    private int cooldown = MINE_TIME;         // сколько тиков осталось

    /** Прожить один тик. Вернуть добытую руду или null, если ещё не готова. */
    public Item tick() {
        cooldown--;
        if (cooldown > 0) {
            return null;            // ещё копаем
        }
        cooldown = MINE_TIME;       // завод на следующую порцию
        return Item.IRON_ORE;
    }
}
```

Вся идея — в `tick()`: каждый вызов уменьшает счётчик `cooldown`, и как только он дошёл до нуля,
бур выдаёт руду и заводит счётчик заново. Это **таймер**: работа занимает время, а не происходит
мгновенно. Такой счётчик-на-тиках встретится потом в каждом «работающем» здании.

Почему бур — просто класс, а не что-то абстрактное? Потому что здание пока ОДНО, и обобщать
нечего. «Здание вообще» (общий интерфейс) появится в следующем уроке, когда рядом встанет второе
здание и станет видно, что у них общего. Придумывать абстракцию для единственного случая — значит
угадывать вслепую; мы этого делать не будем.

---

## 4. Запуск

Осталось то, что заводит мир и печатает происходящее:

```java
// com/rustorio/Main.java
public final class Main {

    private static final int TICKS = 10;

    public static void main(String[] args) {
        Miner miner = new Miner();

        for (int tick = 1; tick <= TICKS; tick++) {
            Item mined = miner.tick();
            if (mined != null) {
                System.out.println("tick " + tick + ": mined " + mined);
            } else {
                System.out.println("tick " + tick + ": ...");
            }
        }
    }
}
```

Запусти:

```
./gradlew game
```

Вывод:

```
tick 1: ...
tick 2: ...
tick 3: mined IRON_ORE
tick 4: ...
tick 5: ...
tick 6: mined IRON_ORE
tick 7: ...
tick 8: ...
tick 9: mined IRON_ORE
tick 10: ...
```

Каждый третий тик — руда. Это и есть первая работающая игра: маленький мир, который тикает, и
здание, которое в нём что-то делает. Дальше всё будет прирастать к этому.

## 5. Задание

1. Собери три файла и добейся такого же вывода через `./gradlew game`.
2. Поменяй `MINE_TIME` на 1 и на 5, перезапусти. Убедись, что руда идёт чаще/реже. Ответь
   письменно: что означает `MINE_TIME = 1`?
3. Заведи в `Main` счётчик всей добытой руды и в конце напечатай итог, например
   `total mined: 3`. (Подсказка: увеличивай счётчик там же, где печатаешь `mined`.)
4. Подумай и ответь письменно: почему бур сделан обычным классом, а не, скажем, интерфейсом
   `Building`? Когда, по-твоему, такой интерфейс станет ОПРАВДАН?
