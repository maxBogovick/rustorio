# Урок 3 — Ящик: буру есть куда копать

В уроке 2 бур встал на карту, но копал «в никуда»: руду добывал, а девать её было некуда.
Заведём **ящик** — второе здание. Поставишь ящик рядом с буром — и бур начнёт складывать
добычу туда, а число на ящике поползёт вверх. Наконец-то видно, что бур приносит пользу.

Попутно случится кое-что важное для всего курса: зданий станет **два**, и мы впервые
почувствуем боль от того, что каждый сорт здания живёт сам по себе. Эту боль в этом уроке мы
специально НЕ лечим — просто заметим. Лечить будем в уроке 4.

---

## 1. Ящик — простой до предела

Бур был про таймер. Ящик — про счётчик: он просто копит, сколько в него положили.

```java
// com/rustorio/Chest.java
public final class Chest {
    private int count;

    public void add()      { count++; }   // положили один предмет
    public int  count()    { return count; }
}
```

Ни сортов предметов, ни вместимости — только число. Так и надо: усложним, когда усложнение
станет РЕШАТЬ проблему, а не создавать её. Сейчас проблемы нет — есть один сорт (руда) и
бесконечный ящик, и этого хватает, чтобы урок был интересным.

Обрати внимание: `Chest` и `Miner` — **два разных класса без общего родителя**. Никакого
`Building`-интерфейса мы пока не вводим. Пусть оба поживут порознь: скоро сам увидишь, где это
начинает мешать.

---

## 2. Мир теперь держит ДВА сорта зданий

Раньше в мире была одна карта — `Map<Long, Miner>`. Теперь добавляется вторая, под ящики, и
рядом с ней — точно такая же обвязка, как у буров:

```java
private final Map<Long, Miner> miners = new HashMap<>();
private final Map<Long, Chest> chests = new HashMap<>();   // ← новая, но всё по образцу

public boolean hasChest(int x, int y) { return chests.containsKey(key(x, y)); }

public void placeChest(int x, int y) {
    if (inBounds(x, y) && isFree(x, y)) {
        chests.put(key(x, y), new Chest());
    }
}
```

Ящику руда не нужна — он стоит на любой свободной клетке (обычно вплотную к буру). А вот «клетка
занята» теперь значит «занята ЛЮБЫМ зданием», не только буром. Поэтому появляется общая проверка:

```java
/** Свободна ли клетка — на ней не должно быть НИКАКОГО здания. */
public boolean isFree(int x, int y) {
    return !hasMiner(x, y) && !hasChest(x, y);
}
```

И `placeMiner` теперь тоже спрашивает `isFree`, а не `!hasMiner` — иначе бур залез бы на ящик.

Уже здесь видно, как всё **двоится**: под каждый сорт здания — своя карта, свой `has…`, свой
`place…`. Пока миримся. Запомни это ощущение — оно нам ещё пригодится.

---

## 3. Бур отдаёт руду соседу

Самое интересное — связать бур с ящиком. В уроке 1 `Miner.tick()` уже возвращал добытую руду
(или `null`, если в этот тик ещё копает). Раньше мы этот результат выбрасывали. Теперь — везём
в соседний ящик:

```java
public void tick() {
    for (Map.Entry<Long, Miner> entry : miners.entrySet()) {
        Item ore = entry.getValue().tick();
        if (ore != null) {                          // в этот тик бур выдал порцию
            long k = entry.getKey();
            deliverToNeighborChest((int) (k >> 32), (int) k);
        }
    }
}
```

Заметь: теперь мир обходит буры **вместе с координатами** (`entrySet`, а не `values`) — ведь
чтобы найти соседа, надо знать, ГДЕ стоит бур. «Сосед» — одна из четырёх смежных клеток:

```java
private Chest neighborChest(int x, int y) {
    Chest c;
    if ((c = chests.get(key(x + 1, y))) != null) return c;
    if ((c = chests.get(key(x - 1, y))) != null) return c;
    if ((c = chests.get(key(x, y + 1))) != null) return c;
    if ((c = chests.get(key(x, y - 1))) != null) return c;
    return null;   // соседа-ящика нет — руда пропадает
}
```

Нет рядом ящика — руда просто теряется (бур всё ещё «копает в никуда»). Есть ящик — `chest.add()`,
и его счётчик растёт. Никаких лент между ними пока нет: руда «телепортируется» из бура в
соседний ящик. Это нарочно просто — плавную передачу по ленте сделаем отдельным уроком.

## 4. Правая кнопка ставит ящик

Левая кнопка уже ставит бур. Ящик повесим на правую — отдельного меню инструментов пока не
нужно:

```java
// InputHandler.handle(...)
if (Gdx.input.isButtonJustPressed(Input.Buttons.LEFT)) {
    TilePos t = camera.pickTile(Gdx.input.getX(), Gdx.input.getY());
    world.placeMiner(t.x(), t.y());
}
if (Gdx.input.isButtonJustPressed(Input.Buttons.RIGHT)) {
    TilePos t = camera.pickTile(Gdx.input.getX(), Gdx.input.getY());
    world.placeChest(t.x(), t.y());
}
```

Как и раньше, ввод не решает, можно ли тут строить, — он лишь сообщает миру, куда ткнули. Все
правила («на руде», «свободно») — в `World`.

---

## 5. Нарисовать ящик и его число

`BuildingRenderer` уже рисовал буры. Дорисуем ящики — и прямо над каждым напишем, сколько в нём
лежит: так на глазах видно, что бур работает.

```java
world.forEachMiner((x, y) ->
        batch.draw(textures.miner[0], grid.x(x), grid.yBottom(y), tile, tile));
world.forEachChest((x, y, count) -> {
    batch.draw(textures.chest, grid.x(x), grid.yBottom(y), tile, tile);
    font.draw(batch, Integer.toString(count), grid.x(x) + 3, grid.yBottom(y) + tile - 3);
});
```

И снова то же двоение: **на каждый сорт здания — свой цикл отрисовки**. В мире двоятся карты и
методы, в отрисовке — циклы. Один и тот же «шов» проходит через весь код.

---

## 6. Запуск

```
./gradlew run
```

1. **ЛКМ по синей руде** — ставим бур.
2. **ПКМ на соседнюю клетку** (вплотную к буру) — ставим ящик.
3. Смотри на число над ящиком: раз в несколько тиков оно **растёт** — это бур принёс руду.

Поставь ящик НЕ рядом с буром — число стоять останется: руде некуда доехать, она теряется.
