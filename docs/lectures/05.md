# Урок 5 — Печь: первая производственная цепочка

До сих пор бур добывал руду, а ящик её копил. Пресновато. Добавим **печь**: она берёт руду,
переплавляет её в железную пластину и отдаёт пластину дальше. Впервые получится настоящая
**цепочка**: бур → печь → ящик. Руда входит с одного конца, готовые пластины капают в ящик с
другого.

И это первый урок, где мы проверяем обещание урока 4: раз общий тип `Building` уже есть — добавить
третье здание должно быть легко, а компилятор сам подскажет, что не забыть.

---

## Чему ты научишься

- **Добавлять здание по готовому шаблону.** Общий тип `Building` уже есть — увидишь, из каких
  ровно кусочков собирается новое здание.
- **Проверка полноты в деле.** Не в теории, а по-настоящему: добавим печь — и компилятор
  ОТКАЖЕТСЯ собирать проект, пока не допишем ветку. Прочитаем реальную ошибку.
- **Здание с входом И выходом.** Печь и принимает (руду), и производит (пластину) — сложнее бура
  и ящика, но собирается из тех же деталей.
- **Замечать НОВЫЙ запашок.** Увидишь, как из-за печи начинает разрастаться другое место — и
  поймёшь, что станет темой следующего рефакторинга.

---

## 1. Цепочка, которую строим

```
   БУР            ПЕЧЬ                 ЯЩИК
 ┌───────┐     ┌─────────┐         ┌─────────┐
 │ добыл │ руда│ копит и  │ пластина│  копит  │
 │ руду  │ ───►│ плавит   │ ───────►│ пластины│
 └───────┘     └─────────┘         └─────────┘
  на руде       между ними          у выхода
```

Бур раз в 3 тика выдаёт руду соседу. Если сосед — печь, руда попадает к ней в буфер. Печь раз в
5 тиков превращает одну руду из буфера в пластину и предлагает её своему соседу. Если тот сосед —
ящик, число пластин в ящике растёт.

---

## 2. Печь как здание

Печь собирается ровно из тех деталей, что мы уже знаем: как у бура — таймер и переопределённый
`tick`; как у ящика — приём предмета. Ново только то, что она делает и то, и другое.

```java
// com/rustorio/Furnace.java
public final class Furnace implements Building {
    private static final int SMELT_TIME = 5;   // тиков на одну пластину
    private static final int BUFFER_MAX = 5;   // сколько руды готова держать в очереди

    private int oreBuffer;
    private int cooldown = SMELT_TIME;

    /** Принять руду от соседа — но только руду и только пока есть место. */
    public boolean accept(Item item) {
        if (item != Item.IRON_ORE || oreBuffer >= BUFFER_MAX) return false;
        oreBuffer++;
        return true;
    }

    @Override
    public void tick(World world, int x, int y) {
        if (oreBuffer == 0) return;                     // плавить нечего
        if (--cooldown > 0) return;                     // ещё плавим
        cooldown = SMELT_TIME;
        oreBuffer--;                                    // одна руда израсходована
        world.offerToNeighbor(x, y, Item.IRON_PLATE);   // готовую пластину — соседу
    }

    public int oreBuffer() { return oreBuffer; }
}
```

Два отличия от ящика стоит проговорить:

- **Печь разборчива.** `accept` берёт НЕ что угодно: только `IRON_ORE` и только пока в буфере есть
  место (`BUFFER_MAX`). Вернёт `false` — сосед поймёт, что не приняли, и оставит предмет себе.
  Ящик, наоборот, берёт всё подряд.
- **Печь производит.** Её `tick` не просто ждёт — он тратит руду и рождает пластину, отдавая её
  тем же `offerToNeighbor`, которым бур отдаёт руду. Один и тот же «кран» на выходе.

Новый предмет для этого и завели — `Item.IRON_PLATE` рядом с `IRON_ORE`. Перечисление выросло
ровно тогда, когда появилось, ЧТО в него добавить.

## 3. Компилятор ловит нас за руку

Дальше — обещанный момент из урока 4. Добавляем печь в закрытый список зданий:

```java
public sealed interface Building permits Miner, Chest, Furnace {   // ← добавили Furnace
```

…собираем — и получаем НЕ работающую игру, а ошибку:

```
BuildingRenderer.java:42: error: the switch statement does not cover all possible input values
            switch (building) {
            ^
```

Вот она, проверка полноты, вживую. `Building` запечатан, компилятор знает ВСЕ его сорта и видит:
в отрисовке разобраны бур и ящик, а печь — нет. Он не даёт собрать проект с дырой. Дописываем
ветку — и только тогда всё компилируется:

```java
case Furnace furnace -> {
    // Топится (в буфере есть руда) — «горячий» спрайт, иначе холодный.
    TextureRegion sprite = furnace.oreBuffer() > 0 ? textures.furnaceOn : textures.furnaceOff;
    batch.draw(sprite, px, py, tile, tile);
    if (furnace.oreBuffer() > 0) {
        font.draw(batch, Integer.toString(furnace.oreBuffer()), px + 3, py + tile - 3);
    }
}
```

Печь ещё и «оживает»: пока в буфере есть руда — рисуем горячий спрайт `furnaceOn`, пусто —
холодный `furnaceOff`. Число над печью показывает, сколько руды ждёт очереди.

**Это и есть выгода `sealed`.** Компилятор не позволил забыть про печь. Не «когда-нибудь всплывёт
баг», а «прямо сейчас, чёрным по белому, вот файл и строка».

## 4. Как руда доезжает до печи

Мир доставляет предметы соседям через `offerToNeighbor` → `offer`. Раньше принять предмет умел
только ящик. Теперь ещё и печь — значит, в маршрутизацию добавляется вторая проверка:

```java
private boolean offer(int x, int y, Item item) {
    Building building = buildings.get(key(x, y));
    if (building instanceof Chest chest)     { chest.accept(item);   return true;  }
    if (building instanceof Furnace furnace) { return furnace.accept(item);        }
    return false;
}
```

И вот тут — **новый запашок**. Замечаешь? Каждое новое «принимающее» здание будет добавлять сюда
ещё один `if (… instanceof …)`. Это ровно та же болезнь, от которой мы лечились в уроке 4, только
переехавшая в другое место. Пока их два — терпимо. Но зерно следующего рефакторинга уже здесь:
дать зданиям ОБЩИЙ способ «принять предмет», чтобы `offer` не перечислял их поимённо.

Пока оставляем как есть — специально. Сначала пусть подрастёт, чтобы боль стала очевидной.

## 5. Как поставить печь

Бур — левой кнопкой, ящик — правой. На печь свободных кнопок мыши не осталось, поэтому вешаем её
на клавишу: **наведи курсор и нажми `F`**.

```java
if (Gdx.input.isKeyJustPressed(Input.Keys.F)) {
    TilePos tile = camera.pickTile(Gdx.input.getX(), Gdx.input.getY());
    world.placeFurnace(tile.x(), tile.y());
}
```

И это тоже сигнал на будущее: **на каждое здание — свой жест** (ЛКМ / ПКМ / клавиша). Зданий
станет пять — жестов не напасёшься. Позже заведём выбор здания и одну кнопку постройки. Пока
хватает и так.

## 6. Запуск

```
./gradlew run
```

Собери цепочку из трёх клеток в ряд:

1. **ЛКМ по руде** — поставь бур.
2. Наведи курсор на СОСЕДНЮЮ клетку, нажми **`F`** — печь.
3. Наведи на клетку за печью, **ПКМ** — ящик.

Смотри: печь то загорается (`furnaceOn`), то гаснет, число руды над ней скачет вверх-вниз, а в
ящике капают уже **пластины**. Ты построил первый маленький завод.

Поставь печь БЕЗ бура рядом — она останется холодной: сырья нет. Поставь бур прямо к ящику, без
печи, — в ящик пойдёт сырая руда. Всё это — следствие правил соседства, а не особых случаев в коде.
