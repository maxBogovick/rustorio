# Урок 7 — Выбор здания: первый элемент интерфейса

К уроку 6 у нас три здания и три РАЗНЫХ жеста постройки: бур — левой кнопкой, ящик — правой,
печь — клавишей `F`. Добавь четвёртое — и жестов не хватит. Схема «один жест на здание» упёрлась
в потолок.

Сделаем как в настоящих играх-фабриках: игрок СНАЧАЛА выбирает здание, а строит всегда одинаково.
Заодно появится первый элемент интерфейса, который показывает состояние игры, — **панель
постройки** (хотбар).

---

## Чему ты научишься

- **Разделять «что строю» и «строю».** Выбор здания — отдельное состояние; постройка — один
  жест, читающий это состояние. Это развязывает «сколько зданий» и «сколько кнопок».
- **Когда enum уместен, а когда — нет.** В уроке 4 мы НЕ заводили enum сортов. Здесь заведём — и
  ты поймёшь, почему это не противоречие: задачи разные.
- **Первый HUD, отражающий состояние.** Панель не статичная — она читает выбор игрока и
  подсвечивает его.
- **Одна дверь в мир.** Как свести три метода постройки к одному входу `place(type, x, y)`.

---

## 1. Что можно построить: `BuildingType`

Чтобы ВЫБИРАТЬ здание, нужен список того, что вообще можно построить, — лёгкие ярлычки, живущие
без самого здания. Для «меню выбора» естественная форма — перечисление:

```java
// com/rustorio/BuildingType.java
public enum BuildingType {
    MINER("Miner"), CHEST("Chest"), FURNACE("Furnace");

    private final String label;
    BuildingType(String label) { this.label = label; }
    public String label() { return label; }
}
```

**«Погоди, в уроке 4 мы же нарочно НЕ заводили сорт-enum!»** Верно — и это не противоречие,
потому что задача другая:

| Урок 4 | Урок 7 |
|---|---|
| РАЗЛИЧИТЬ поведение готового здания | ПЕРЕЧИСЛИТЬ, что можно построить |
| решает полиморфизм (`sealed` + методы) | решает меню (список ярлыков) |
| работаем с ЭКЗЕМПЛЯРОМ здания | ярлык живёт БЕЗ экземпляра |

`BuildingType.MINER` — это не бур, а «пункт меню, по которому можно поставить бур». Инструмент под
конкретную задачу, а не дубликат `sealed`-иерархии.

---

## 2. Одна дверь постройки в мире

Раньше мир имел три отдельные двери: `placeMiner`, `placeChest`, `placeFurnace`. Они и остаются —
у каждого своё правило (буру нужна руда). Но вводу теперь удобнее ОДНА дверь, которая по выбранному
сорту ведёт к нужному правилу:

```java
// World
public void place(BuildingType type, int x, int y) {
    switch (type) {
        case MINER   -> placeMiner(x, y);
        case CHEST   -> placeChest(x, y);
        case FURNACE -> placeFurnace(x, y);
    }
}
```

И зеркальная возможность — снести здание, чтобы игрок мог исправить ошибку:

```java
public void removeBuilding(int x, int y) {
    buildings.remove(key(x, y));
}
```

Правила места по-прежнему живут в мире; `place` лишь маршрутизирует «игрок строит ВОТ ЭТО» к
нужному из них.

## 3. Ввод: выбрал → построил

Теперь у ввода есть ПАМЯТЬ — что сейчас выбрано:

```java
// InputHandler
private BuildingType selected = BuildingType.MINER;   // с чего начинаем

public BuildingType selected() { return selected; }   // HUD спросит, что показать
```

Клавиши `1/2/3` меняют выбор, а кнопки мыши всегда делают одно и то же — строят выбранное / сносят:

```java
private void handleBuildSelection() {
    if (Gdx.input.isKeyJustPressed(Input.Keys.NUM_1)) selected = BuildingType.MINER;
    if (Gdx.input.isKeyJustPressed(Input.Keys.NUM_2)) selected = BuildingType.CHEST;
    if (Gdx.input.isKeyJustPressed(Input.Keys.NUM_3)) selected = BuildingType.FURNACE;
}

// в handle(...):
if (Gdx.input.isButtonJustPressed(Input.Buttons.LEFT))  world.place(selected, t.x(), t.y());
if (Gdx.input.isButtonJustPressed(Input.Buttons.RIGHT)) world.removeBuilding(t.x(), t.y());
```

Вот она, развязка: **число зданий больше не упирается в число кнопок.** Хоть двадцать зданий —
жеста всё так же два (построить/снести), а выбор растёт в списке, а не в пальцах.

## 4. Панель постройки — первый HUD с состоянием

Игроку надо видеть, что выбрано. HUD теперь читает выбор и рисует панель, подсвечивая текущий
пункт скобками:

```java
void render(BuildingType selected) {
    ...
    font.draw(batch, hotbar(selected), 20, top - 44);
    ...
}

private static String hotbar(BuildingType selected) {
    StringBuilder sb = new StringBuilder("Build:   ");
    for (BuildingType type : BuildingType.values()) {       // список строит сам себя
        int number = type.ordinal() + 1;
        if (type == selected) sb.append("[ ").append(number).append(' ').append(type.label()).append(" ]    ");
        else                  sb.append("  ").append(number).append(' ').append(type.label()).append("     ");
    }
    return sb.toString();
}
```

На экране получается строка вроде:

```
Build:   [ 1 Miner ]    2 Chest     3 Furnace
```

Нажми `2` — скобки перепрыгнут на `Chest`. Это первый кусочек интерфейса, который не просто висит,
а ОТРАЖАЕТ состояние: HUD читает `selected` и показывает его. Панель перебирает
`BuildingType.values()` — добавишь в enum новый сорт, он появится в панели сам, без правок HUD.

Чтобы выбор дошёл до HUD, его протянули по цепочке кадра: `GameScreen` спрашивает у ввода
`input.selected()` и передаёт в `renderer.render(world, selected, delta)`, а тот — в HUD. Данные
текут в одну сторону: ввод ЗНАЕТ выбор, рендер его ПОКАЗЫВАЕТ.
