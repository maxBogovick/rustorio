# Урок 14 — Observer: второй слушатель без правок мира

В уроке 9 статистика встала на прямой вызов: как только предмет доезжает до
`World.offerToNeighbor`, мир САМ, по имени, зовёт `stats.record(item)`. Работало отлично — пока
слушатель был ровно один. Сегодня заведём второго: **лог последних событий**, показывающий на
экране, что производилось только что. И проверим прямой вопрос — сколько строк в `World` придётся
поменять, чтобы он появился?

Ответ, к которому идём: ни одной. Это и есть паттерн **Observer**.

---

## Чему ты научишься

- **Разводить источник события и того, кто на него реагирует.** Мир будет знать только «кто-то
  хочет получать эти события», а не «вот статистика, я зову именно её».
- **Список слушателей вместо одного жёстко зашитого.** Один и тот же метод оповещения работает
  для одного слушателя, для трёх, для нуля — количество ему безразлично.
- **Ссылку на метод как подписку, без интерфейса-обёртки на классе.** `ProductionStats` не будет
  ничего «реализовывать» — тот же приём, что уже видели в `SortRule.ORE_FORWARD` (урок 12).
- **Где именно окупается это разведение.** Не абстрактно «гибкость», а конкретно: `World.java`
  не открывается ради нового слушателя.

---

## 1. Что не так с прямым вызовом

```java
// как было (урок 9)
public boolean offerToNeighbor(int x, int y, Item item) {
    stats.record(item);
    return offer(x + 1, y, item) || ...
}
```

Работает, но `World` знает про `ProductionStats` не как про «что-то, кому интересны события», а
буквально по имени поля и по имени метода. Захочешь второго получателя события — лог, будущий
счётчик достижений, что угодно — придётся снова открывать `offerToNeighbor` и дописывать вторую
строчку вызова. Точно то же самое дублирование по духу, что убирали в уроке 6: код, который
перечисляет ПОИМЁННО, вместо того чтобы спросить «кто вообще хочет знать» и обойти всех разом.

---

## 2. Общий язык между миром и слушателями

```java
// com/rustorio/ProductionListener.java
@FunctionalInterface
public interface ProductionListener {
    void onProduced(Item item);
}
```

Один метод: «предмет произведён, вот какой». Мир будет держать СПИСОК таких слушателей вместо
одного `ProductionStats`:

```java
// World
private final List<ProductionListener> productionListeners = new ArrayList<>();

public World(int width, int height) {
    this.width = width;
    this.height = height;
    productionListeners.add(stats::record);
}

public void addProductionListener(ProductionListener listener) {
    productionListeners.add(listener);
}
```

`stats::record` — ссылка на метод, а не отдельный класс-обёртка. `ProductionStats` как был, так и
остался: он НЕ реализует `ProductionListener`, даже не знает о его существовании. Java просто
проверяет, что форма подходит — метод берёт `Item` и ничего не возвращает, значит годится. Тот же
трюк, что `SortRule.ORE_FORWARD = item -> item == Item.IRON_ORE` в уроке 12: не пишем класс ради
одной реализации, если хватает ссылки.

---

## 3. Оповещение — одна строка, а не одна строка НА КАЖДОГО слушателя

```java
public boolean offerToNeighbor(int x, int y, Item item) {
    for (ProductionListener listener : productionListeners) {
        listener.onProduced(item);
    }
    return offer(x + 1, y, item) || ...
}
```

Цикл по списку — и неважно, сколько там слушателей: один, три или (в самом первом запуске) вообще
ни одного. Раньше добавление получателя события значило правку ИМЕННО этого метода; теперь —
вызов `world.addProductionListener(...)` СНАРУЖИ, и `offerToNeighbor` эту правку не видит вовсе.

---

## 4. Второй слушатель: лог последних событий

```java
// com/rustorio/ProductionLog.java
public final class ProductionLog implements ProductionListener {

    private static final int CAPACITY = 5;
    private final List<Item> recent = new ArrayList<>();

    @Override
    public void onProduced(Item item) {
        recent.add(0, item);
        if (recent.size() > CAPACITY) {
            recent.remove(recent.size() - 1);
        }
    }

    public List<Item> recent() {
        return List.copyOf(recent);
    }
}
```

В отличие от `ProductionStats` (подписанной ссылкой на метод), `ProductionLog` — полноценный
класс, реализующий `ProductionListener`: он не просто пересчитывает, а хранит небольшую историю,
ему есть смысл быть отдельным типом. Оба варианта подписки — ссылка на метод и целый класс —
законны; выбор зависит от того, сколько состояния несёт слушатель.

Важно: `ProductionLog` НИЧЕГО не знает про `ProductionStats`, а `World` ничего не знает про
`ProductionLog` — только про интерфейс. Подключается он одной строкой СНАРУЖИ:

```java
// GameScreen
private final ProductionLog productionLog = new ProductionLog();

public GameScreen() {
    this.world = new World(GfxConfig.GRID_W, GfxConfig.GRID_H);
    world.addProductionListener(productionLog);
    ...
}
```

Проверь сам: открой `World.java` и `git diff` на нём после появления `ProductionLog` — метод
`offerToNeighbor` не тронут. Это и есть обещанный урок целиком, в одной проверке.

## 5. HUD показывает то, что читает независимо от статистики

`HudRenderer` получает `ProductionLog` рядом с `ProductionStats` и строит из него ещё одну строку,
тем же приёмом «список строит себя»:

```java
private static String recent(ProductionLog log) {
    StringBuilder sb = new StringBuilder("Recent:   ");
    for (Item item : log.recent()) {
        sb.append(item.name()).append("  ");
    }
    return sb.toString();
}
```

На экране появляется `Recent:   IRON_ORE  IRON_ORE  IRON_PLATE  ...` — самый свежий предмет
слева, и обновляется независимо от строки `Produced:` над ней. Два наблюдателя одного события,
показанные рядом, ничего друг о друге не знающие.

---

## 6. Observer — не то же самое, что Strategy (урок 12)

Оба паттерна про «мир не знает конкретики заранее», но развязывают РАЗНОЕ:

| | Strategy (урок 12) | Observer (урок 14) |
|---|---|---|
| Сколько получателей у решения | Ровно один — здание спрашивает СВОЁ правило | Сколько угодно — событие видят ВСЕ подписанные |
| Что возвращает слушатель/правило | Ответ, который влияет на дальнейшее поведение (`forward` да/нет) | Ничего — просто узнаёт и делает что хочет у себя |
| Кто инициирует | Здание спрашивает правило само | Мир рассылает всем, никого не спрашивая |

Strategy — «дай мне решение». Observer — «вот что случилось, дальше сами».

## 7. Запуск

```
./gradlew run
```

Строй цепочки, смотри на HUD: `Produced:` растёт числами, `Recent:` под ней крутит последние
предметы. Останови постройку — обе строки замирают одновременно, потому что оба слушателя видят
одно и то же событие.
