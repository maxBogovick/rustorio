# Урок 15 — Command: действие как объект

Ошибся клеткой — сносишь ПКМ и строишь заново. Работает, но раздражает: обратной кнопки нет. Хуже:
если снесённое здание успело что-то накопить (руду в печи, пластины в ящике), это состояние просто
исчезает. Заведём **отмену** (Ctrl+Z) и **повтор** (Ctrl+Y) — по-настоящему, а не притворно: печь,
восстановленная отменой, должна помнить, сколько в ней было руды.

Это паттерн **Command**: постройка и снос перестают быть прямыми вызовами и становятся ОБЪЕКТАМИ,
которые умеют не только «сделать», но и «откатить сделанное».

---

## Чему ты научишься

- **Превращать действие в объект.** Не «мир, поставь сюда бур» напрямую, а «вот объект-намерение,
  примени его к миру» — и тот же объект знает, как себя откатить.
- **Почему отмена сноса — не просто повторная постройка.** Восстановить нужно ИМЕННО то здание,
  что стояло, с его накопленным состоянием, — не новое такое же с нуля.
- **Стек вместо одной переменной.** Отмена не одношаговая: нужна история, и она естественно
  ложится на две стопки — сделанное и откаченное.
- **Где паттерн окупается на следующей фиче.** `CompositeAction` — несколько действий как одно —
  не потребует ни строчки изменений в истории отмены.

---

## 1. Действие — не вызов, а объект с двумя методами

```java
// com/rustorio/PlayerAction.java
public interface PlayerAction {
    boolean apply(World world);   // применить; true — если реально что-то изменилось
    void undo(World world);       // откатить ровно то, что сделал apply
}
```

Постройка и снос — его первые две реализации:

```java
// PlaceAction
public boolean apply(World world) { return world.place(type, x, y); }
public void undo(World world)     { world.removeBuilding(x, y); }
```

```java
// RemoveAction
private Building removed;   // запоминаем в apply, чтобы вернуть в undo

public boolean apply(World world) {
    removed = world.removeBuilding(x, y);
    return removed != null;
}
public void undo(World world) {
    world.restore(x, y, removed);   // ИМЕННО этот объект, не новый
}
```

`RemoveAction.undo` зовёт `world.restore`, а не `world.place`, — тот же приём, что уже был в
загрузке сохранения (урок 10): правила постройки уже были пройдены, когда здание ставили в первый
раз, переспрашивать их сейчас незачем. И именно поэтому `World.removeBuilding` теперь ВОЗВРАЩАЕТ
снесённое здание, а не просто выкидывает его:

```java
// как было (до урока 15)
public void removeBuilding(int x, int y) {
    buildings.remove(key(x, y));
}

// как стало
public Building removeBuilding(int x, int y) {
    return buildings.remove(key(x, y));
}
```

`Map.remove` и раньше возвращал удалённое значение — мы просто перестали его выбрасывать. Раз
`RemoveAction` держит ССЫЛКУ на снесённый объект, а не создаёт новый, откат восстанавливает печь
С ТЕМ ЖЕ буфером руды, ящик — С ТЕМ ЖЕ количеством. Не притворная отмена, настоящая.

По той же причине `place*` и `place` теперь возвращают `boolean` — было ли что запоминать:

```java
public boolean placeMiner(int x, int y) {
    if (inBounds(x, y) && hasOre(x, y) && isFree(x, y)) {
        buildings.put(key(x, y), new Miner());
        return true;
    }
    return false;
}
```

Клик по занятой клетке или мимо руды теперь честно говорит «ничего не вышло» — и историю отмены
этим не засоряет.

## 2. История — две стопки, не одна переменная

```java
// com/rustorio/ActionHistory.java
public final class ActionHistory {
    private final Deque<PlayerAction> done = new ArrayDeque<>();
    private final Deque<PlayerAction> undone = new ArrayDeque<>();

    public void perform(World world, PlayerAction action) {
        if (action.apply(world)) {
            done.push(action);
            undone.clear();   // новое действие обрывает «будущее» — старый redo больше не в счёт
        }
    }

    public void undo(World world) {
        if (done.isEmpty()) return;
        PlayerAction action = done.pop();
        action.undo(world);
        undone.push(action);
    }

    public void redo(World world) {
        if (undone.isEmpty()) return;
        PlayerAction action = undone.pop();
        action.apply(world);
        done.push(action);
    }
}
```

Почему две стопки, а не одна с указателем позиции? Потому что `undo`/`redo` — это ровно «переложить
действие из одной стопки в другую», а не «подвигать индекс» — код читается как объясняется словами,
без арифметики на границах массива.

`undone.clear()` в `perform` — важная деталь: если ты отменил три действия, а потом построил ЧТО-ТО
НОВОЕ, три старых «повтора» больше не имеют смысла (мир уже не тот, к которому они применялись бы
осмысленно) — обычное поведение undo/redo в любом редакторе.

## 3. Ввод отдаёт намерения истории, а не миру напрямую

```java
// InputHandler.handle
if (Gdx.input.isButtonJustPressed(Input.Buttons.LEFT)) {
    TilePos tile = camera.pickTile(Gdx.input.getX(), Gdx.input.getY());
    history.perform(world, new PlaceAction(selected, tile.x(), tile.y()));
}
if (Gdx.input.isButtonJustPressed(Input.Buttons.RIGHT)) {
    TilePos tile = camera.pickTile(Gdx.input.getX(), Gdx.input.getY());
    history.perform(world, new RemoveAction(tile.x(), tile.y()));
}

boolean ctrl = Gdx.input.isKeyPressed(Input.Keys.CONTROL_LEFT)
        || Gdx.input.isKeyPressed(Input.Keys.CONTROL_RIGHT);
if (ctrl && Gdx.input.isKeyJustPressed(Input.Keys.Z)) history.undo(world);
if (ctrl && Gdx.input.isKeyJustPressed(Input.Keys.Y)) history.redo(world);
```

`InputHandler` по-прежнему не решает, МОЖНО ли строить, — это как всегда забота мира
(`PlaceAction.apply` зовёт `world.place`, а не проверяет правила сам). Изменилось только то, что
между кликом и миром встал объект-действие, а между действием и его результатом — история.

## 4. Мораль: `CompositeAction` — обещанная выгода задаром

Хочешь одним отменяемым шагом поставить сразу несколько зданий? Не трогай `ActionHistory` вообще:

```java
// com/rustorio/CompositeAction.java
public final class CompositeAction implements PlayerAction {
    private final List<PlayerAction> actions;

    public boolean apply(World world) {
        boolean any = false;
        for (PlayerAction action : actions) if (action.apply(world)) any = true;
        return any;
    }
    public void undo(World world) {
        for (int i = actions.size() - 1; i >= 0; i--) actions.get(i).undo(world);
    }
}
```

`CompositeAction` — ОБЫЧНАЯ реализация `PlayerAction`, такая же, как `PlaceAction`. `ActionHistory`
про неё ничего не знает и знать не должно: с её точки зрения это всё то же одно действие с
`apply`/`undo`. Проверено: `git diff` на `ActionHistory.java` после появления `CompositeAction` —
пустой. Это и есть обещание Command: правильно построенный паттерн окупается на следующей фиче
без единой правки уже написанного кода.

## 5. Запуск

```
./gradlew run
```

1. Построй бур → печь → ящик, дай цепочке поработать несколько тиков.
2. Снеси печь ПКМ — число руды в буфере пропало вместе с ней.
3. **Ctrl+Z** — печь вернулась НА МЕСТО, и число в буфере то же самое, что было перед сносом.
4. **Ctrl+Y** — печь снова снесена (повтор).
5. Построй что-то новое — попробуй Ctrl+Y снова: повторять больше нечего, новое действие обрывает
   старую историю.
