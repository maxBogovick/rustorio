# D3 — Шаблон Command: отмена и чертежи

Цель урока — шаблон **Command**: действие как объект. В проекте он уже есть (отмена/повтор
построек), поэтому урок другой по форме: сначала разбираем готовую реализацию, затем
РАСШИРЯЕМ её до чертежей (снять область зданий и штамповать её одним отменяемым действием).
Расширение почти не пишет нового кода отмены — в этом и мораль: правильно построенный
паттерн окупается на следующей фиче.

**Зависит от:** [D1](D1.md). Новое — в `model`, `game`, `input`. Превью использует готовый
видео-API (`docs/ENGINE-VIEW-API.md`), правок в `render` под фичу нет.

---

## 1. Что уже есть

Command овеществляет «поставить»/«снести» в объект, умеющий примениться и откатиться.

```java
// game/action/PlayerAction.java
public sealed interface PlayerAction permits PlaceBuilding, RemoveBuilding, CompositeAction {
    void apply(World world);    // выполнить (и запомнить прежнее — мини-Memento)
    void revert(World world);   // откатить последний apply
    boolean hadEffect();        // изменил ли мир на самом деле
}
```

Три готовых кирпича:

- `PlaceBuilding` — команда с памятью для отката: в `apply` запоминает, что стояло на клетке
  до неё, в `revert` возвращает как было.
- `CompositeAction` — список команд как одна (Composite): `apply` по порядку, `revert` — в
  ОБРАТНОМ. Одна отмена убирает весь жест (например, проведённую мышью линию лент).
- `ActionHistory` — инвокер: два стека, «сделано» и «отменено». `undo` снимает верхнюю,
  откатывает, кладёт в «отменено»; `redo` зеркально.

`GameState.perform` связывает их: `action.apply(world); history.push(action);`.

Задача урока — добавить чертёж, **не трогая** эти четыре типа.

---

## 2. Наивная штамповка

Пусть чертёж — просто список зданий с координатами, а вставка кладёт их в мир напрямую:

```java
void paste(World world, Cell origin, List<Stamp> stamps) {
    for (Stamp s : stamps) {
        world.place(origin.x() + s.dx(), origin.y() + s.dy(),
                Building.create(s.tool(), s.dir()));
    }
}
```

Следствия:

1. **Мимо истории.** `world.place` в обход `ActionHistory` — вставку нельзя отменить.
2. **Либо отмена по клетке.** Если класть каждую постройку отдельной командой через
   `perform`, отмена уберёт оттиск не целиком, а по одному зданию — не то, что ждёт игрок.
3. **Дублирование.** Логика «поставить и запомнить прежнее для отката» уже написана в
   `PlaceBuilding`; здесь она повторяется руками, но без отката.

Всё это уже решено в существующих командах. Значит, чертёж должен их ПЕРЕИСПОЛЬЗОВАТЬ, а не
обходить.

---

## 3. Чертёж как поставщик команд

Ключевая мысль: команда — конкретное действие («поставить ЭТО на ЭТУ клетку»). Чертёж на шаг
выше — это ОТНОСИТЕЛЬНЫЙ, переносимый шаблон, который при штамповке ПОРОЖДАЕТ команды под
нужное место. Хранится один раз, штампуется в любом числе мест.

### 3.1. Обратная сторона фабрики: `Building.tool()`

Чтобы снять здание в шаблон и потом воссоздать, нужен его тип. `Building.create` умеет
`Tool → Building`; для съёма нужен обратный ход. Добавляем в контракт `Building` метод —
тип-сумма отвечает о себе сам, без внешнего `switch`:

```java
// model/Building.java
Tool tool();
// в каждом здании — одна строка, например:
@Override public Tool tool() { return Tool.MINER; }
```

### 3.2. Сам чертёж

Снятие — относительные координаты + тип + направление (без содержимого: штампуются свежие
пустые здания). Штамповка собирает `CompositeAction` из `PlaceBuilding` — отмену и группировку
дают готовые команды.

```java
// game/Blueprint.java
public final class Blueprint {

    public record Stamp(int dx, int dy, Tool tool, Direction dir) { }

    private final List<Stamp> stamps;
    private Blueprint(List<Stamp> stamps) { this.stamps = List.copyOf(stamps); }

    public boolean isEmpty() { return stamps.isEmpty(); }

    /** Снять чертёж с прямоугольника a..b. Смещения — от верхнего-левого угла. */
    public static Blueprint capture(World world, Cell a, Cell b) {
        int minX = Math.min(a.x(), b.x()), minY = Math.min(a.y(), b.y());
        int maxX = Math.max(a.x(), b.x()), maxY = Math.max(a.y(), b.y());
        List<Stamp> stamps = new ArrayList<>();
        for (int y = minY; y <= maxY; y++) {
            for (int x = minX; x <= maxX; x++) {
                if (!world.inBounds(x, y)) continue;
                Building b2 = world.tile(x, y).building();
                if (b2 == null) continue;
                Direction dir = b2.direction().orElse(Direction.EAST);
                stamps.add(new Stamp(x - minX, y - minY, b2.tool(), dir));
            }
        }
        return new Blueprint(stamps);
    }

    /** Команда штамповки от origin: композит из PlaceBuilding — ОДНА отмена. */
    public CompositeAction stampAt(Cell origin) {
        List<PlayerAction> actions = new ArrayList<>();
        for (Stamp s : stamps) {
            Cell cell = new Cell(origin.x() + s.dx(), origin.y() + s.dy());
            actions.add(new PlaceBuilding(cell, Building.create(s.tool(), s.dir())));
        }
        return new CompositeAction(actions);
    }

    /** Абсолютные клетки оттиска от origin — для превью. */
    public List<Cell> cells(Cell origin) {
        List<Cell> out = new ArrayList<>();
        for (Stamp s : stamps) out.add(new Cell(origin.x() + s.dx(), origin.y() + s.dy()));
        return out;
    }
}
```

`Blueprint` НЕ реализует `PlayerAction` и не входит в его `permits`: это не команда, а её
поставщик. Sealed-набор действий остаётся закрытым и нетронутым.

## 4. Встраивание

### 4.1. Состояние инструмента в `GameState`

```java
private @Nullable Cell blueprintCorner = null;   // первый угол выделения
private @Nullable Blueprint heldBlueprint = null; // снятый чертёж «в руке»

/** C: первое нажатие — угол, второе — снять область «угол → курсор». */
public void blueprintKey() {
    hover().ifPresent(cell -> {
        if (blueprintCorner == null) {
            blueprintCorner = cell;
        } else {
            heldBlueprint = Blueprint.capture(world, blueprintCorner, cell);
            blueprintCorner = null;
        }
    });
}

/** V: штамповать от курсора — ОДНОЙ отменяемой командой. */
public void stampBlueprint() {
    if (heldBlueprint == null || heldBlueprint.isEmpty()) return;
    hover().ifPresent(origin -> perform(heldBlueprint.stampAt(origin)));
}

public void clearBlueprint() { blueprintCorner = null; heldBlueprint = null; }
```

`stampBlueprint` идёт через `perform` — оттиск любого размера ложится в историю одним `Ctrl+Z`.

### 4.2. Клавиши (`input`) и превью (`overlay`)

```java
// input/InputHandler.java
if (Gdx.input.isKeyJustPressed(Input.Keys.C)) game.blueprintKey();
if (Gdx.input.isKeyJustPressed(Input.Keys.V)) game.stampBlueprint();
if (Gdx.input.isKeyJustPressed(Input.Keys.X)) game.clearBlueprint();
```

```java
// game/GameState.prepareFrame — превью подсветкой, без правок render
hover().ifPresent(cell -> {
    if (blueprintCorner != null) {
        highlightRect(blueprintCorner, cell, Tint.RANGE);        // что попадёт в чертёж
    } else if (heldBlueprint != null) {
        for (Cell c : heldBlueprint.cells(cell)) {
            overlay.highlight(c.x(), c.y(), Tint.GHOST);         // куда ляжет оттиск
        }
    }
});
```

## 5. Что показал урок

Новый код фичи — по сути один класс `Blueprint` и один метод `Building.tool()`. Отмена,
память отката, группировка в один шаг — НЕ переписаны: их дали готовые `PlaceBuilding` и
`CompositeAction`. Это прямая выгода Command: команда — переиспользуемый кирпич, и следующая
фича (чертёж) собирается из кирпичей, а не из сырого `world.place`.

## 6. Задание

1. Снятие берёт тип и направление, но не СОДЕРЖИМОЕ (у сортировщика — его политику; у ящика
   — счётчик). Это осознанное упрощение. Решите, что из этого стоит копировать, и добавьте в
   `Stamp` соответствующее поле; `PlaceBuilding`/`CompositeAction`/`ActionHistory` не трогайте.
2. Сделайте штамповку зеркалимой по горизонтали (клавиша-модификатор): при съёме или штампе
   инвертируйте `dx` и разверните направления. Вся отмена продолжит работать даром.
